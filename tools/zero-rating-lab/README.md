# 🧪 zero-rating-lab — المختبر العملي المحلي (localhost فقط)

تجربة عملية **تراها بعينيك** لكيفية عمل خدع «النت المجاني» وكيف تُغلق —
كل شيء داخل جهازك على `127.0.0.1`. **لا يخرج أي باكت من جهازك**، ولا يوجد
أي هوست حقيقي أو إعداد خدع جاهز. الأسماء المستخدمة (`games.example` /
`social.example` / `seller.lab`) تجريدية بالكامل.

## لماذا مختبر محلي وليس «هوستات حقيقية»؟

| ما قد تسمعه في السوق | موقفنا |
|---|---|
| «قائمة هوستات مجانية تعمل» | ❌ لا نوفرها — هذه القوائم هي نفسها المنتج المسروق الذي يُباع للضحايا |
| «كيف أصطاد هوستات على الشبكة» | ❌ لا نعلّم الحصاد ضد شبكات حقيقية — استخدام غير مشروع |
| «اشترِ سيرفر وأضف النفق» | ❌ لا نكتب دليل بناء بنية النقوب — هذا هو نموذج عمل النصابين |
| «أريد أفهم بتجربة» | ✅ **هذا المختبر** — نفس الميكانيكا، بلا ضحية وبلا مخالفة |

التجربة على جهازك لا تحتاج أن تكون «سرية» — لأنها تعليم قانوني بلا أي اتصال بشبكة أحد.

## التشغيل (أمر واحد)

```bash
cd tools/zero-rating-lab
python3 lab.py
```

يشغّل المختبر **4 سيناريوهات** ويُغلق تلقائياً بعد الطباعة:

1. **① تصفح عادي** → موقع «أخبار» يُحتسب في الفاتورة ✅
2. **② الخدعة** → العميل يتصل بـ«سيرفر البائع» لكنه يرفع `Host: games.example`
   → البوابة الضعيفة تقول «مفروض!» و**تُصفِّر العدّ** 😱
   → وفي المقابل **سيرفر البائع يطبع كل ما رآه عنك** (المسار، الكوكيز، الهوية) 👁️
3. **③ الإصلاح** → نفس التضليل ضد بوابة تُمسك `Host↔الوجهة` → **421** والخدعة تموت ✅
4. **④ CONNECT** → الضعيفة تفتح النفق (`200`)، الآمنة ترفض (`403`) ✅

في النهاية تُطبع «فاتورة» المختبر: كم بايت احتُسب، كم «سُرِق» بلا عدّ، وكم طلب رُفض.

## تجربة يدوية (اختيارية)

```bash
python3 lab.py --serve
```

ثم من طرفية أخرى:

```bash
# تصفح عادي (محسوب)
curl -x http://127.0.0.1:8080 http://news.example/

# التضليل (البوابة الضعيفة): وجهة البائع الحقيقية + Host مزوّر
curl -x http://127.0.0.1:8080 -H "Host: games.example" http://seller.lab:9090/offer

# الوجهة المفروضة الشرعية (لا تُحتسب كما يجب)
curl -x http://127.0.0.1:8080 http://games.example/
```

لتغيير البوابة إلى الوضع الآمن: عدّل `MODE = {"name": "fixed"}` أعلى `lab.py`.

## خريطة المختبر ↔ العالم الحقيقي

| المختبر (تجريد) | في الحقيقة |
|---|---|
| البوابة (8080) | نظام فوترة/بروكسي المشغّل في شريحة الهاتف |
| `games.example`, `social.example` | الوجهات المفروضة في باقتك (ألعاب/سوشيال) |
| `news.example` | أي وجهة عادية محسوبة |
| `seller.lab:9090` | سيرفر البائع الذي ينتهي عنده النفق |
| رأس `Host` المزوّر | تضليل SNI/Host في أدوات النفق |
| `CONNECT` | فتح أنفاق VPN/التوجيه |
| وضع `fixed` | الإصلاحات التي يجب أن ينفذها كل مشغّل |

## الدروس العملية (ما ستراه بنفسك)

1. **أي فوترة تثق في حقل يتحكم به العميل** (Host/SNI) **قابلة للخداع** — هذه «الثغرة» كلها.
2. **النفق ينتهي عند البائع**: اطبعات السيناريو ② تُريك حرفياً أن الكوكيز والهوية وصلت
   لسيرفره. «الاشتراك الشهري» = تسليم بياناتك لطرف ثالث كل يوم.
3. **العلاج مطبَّق أمامك في ③ و④**: مطابقة Host↔الوجهة (421)، إغلاق CONNECT،
   وقوائم وجهات صارمة. أي شبكة تفعل هذا تقتل الخدع من جذورها.

## التفاصيل التقنية

- Python 3.8+ **بالمكتبة القياسية فقط** — لا تثبيت أي شيء.
- خوادم `ThreadingHTTPServer` على `127.0.0.1` حصراً (لا `0.0.0.0`) — لا يمكن الوصول إليها من الخارج.
- المختبر يُعيد بناء الحقيقة المُجرَّدة: في الشبكات الحقيقية تُحدَّد الوجهة بـ IP/SNI،
  والخطأ هو **الثقة بمقياس يقرأ حقولاً يتحكم بها العميل دون مطابقتها بالوجهة الفعلية**.
- الخروج برمز 0 يعني نجاح كل السيناريوهات (المختبر يتحقق من النتائج بنفسه).
